# 协议规范 v0.1（草案）

## 范围

协议跑在 WebSocket 二进制帧上，浏览器是客户端，一条连接承载多个文件流。

TLS 1.3 由 nginx 终止，管通道机密性。协议自己管四件事：身份（挑战签名）、流（多路复用）、内容（块级校验与续传对账）、边界（帧长、连接、速率）。报告里的帧头图与时序图都从这份文档出。

## 帧

16 字节定长头，大端：

```
偏移  0      2    3    4    5    6     7            11              15
    +------+----+----+----+----+------+------------+---------------+
    | magic| ver|type|flg | rsv|stream|    seq     |    length     |
    +------+----+----+----+----+------+------------+---------------+
     2字节  1    1    1    1    2        4字节           4字节
```

| 字段 | 长度 | 含义 |
| --- | --- | --- |
| magic | 2 | 固定 `0x5654`（字母 VT），对不上直接断 |
| ver | 1 | 协议版本，当前 1 |
| type | 1 | 消息类型，1 到 19 |
| flags | 1 | bit0 分片末尾，其余保留 |
| rsv | 1 | 保留，发送方写 0，接收方忽略 |
| stream | 2 | 流号，0 是控制流 |
| seq | 4 | 流内序号，从 1 递增，发现丢帧与乱序 |
| length | 4 | 载荷长度，上限 1 MiB |

载荷两种形态：

- DATA：`offset:u64 || 块`，不转文本，大文件不过 JSON。
- 其余消息：UTF-8 JSON 对象，键排序、无空格，上限 64 KiB。

接收方先读 16 字节，按 length 再读载荷。长度前置让粘包没有歧义，上限让服务端读到帧头就能拒绝超长帧，不会先分配内存。

## 消息

| 值 | 消息 | 方向 | 载荷 |
| --- | --- | --- | --- |
| 1 | HELLO | C→S | `{ver, user, caps}` |
| 2 | HELLO_ACK | S→C | `{ver, sid, nonce}` |
| 3 | AUTH_CHALLENGE | S→C | `{nonce}` 32 字节随机 |
| 4 | AUTH_RESPONSE | C→S | `{sig, pub}` 对 `nonce‖sid` 的签名与公钥 |
| 5 | AUTH_OK | S→C | `{ticket, rate, quota}` |
| 6 | LIST | C→S | `{path}` |
| 7 | LIST_OK | S→C | `{entries:[{name,size,mtime}]}` |
| 8 | OPEN | C→S | `{path, mode, size, root}` mode 为 up 或 down |
| 9 | OPEN_OK | S→C | `{stream, offset}` |
| 10 | DATA | 双向 | `offset:u64 ‖ 块` |
| 11 | ACK | S→C | `{offset}` 已落盘的位置 |
| 12 | DONE | 双向 | `{size, sha256}` |
| 13 | DONE_OK | 双向 | `{stream}` |
| 14 | RESUME | C→S | `{ticket}` |
| 15 | RESUME_OK | S→C | `{sid, streams:[{stream,mode,path,offset,size,root}]}` |
| 16 | PING | C→S | 空 |
| 17 | PONG | S→C | 空 |
| 18 | ERROR | 双向 | `{code, msg, stream}` |
| 19 | BYE | 双向 | `{reason}` |

## 状态机

连接五个状态：CONNECTED 只认 HELLO，5 秒内不收就断；CHALLENGED 等签名；AUTHED 才进数据阶段；数据阶段里 OPEN 开流、DATA 搬块、DONE 收尾，多个流并行；CLOSED 后会话保留 10 分钟，凭 ticket 走 RESUME 回来。

票据是服务端签名的 JSON：`{sid, user, pub, exp}`，绑定客户端公钥，签名对象是服务端每次新发的 nonce，旧票据换连接也无法重放。

## 时序模块

报告要给每个模块画一张时序图，这里先定每张图有哪几步。

1. 建连与心跳：浏览器 `new WebSocket(wss://…)` → HELLO/HELLO_ACK → 每 30 秒 PING/PONG → 120 秒内没有 PONG 双向断开。
2. 认证：HELLO_ACK 带 nonce → 浏览器用私钥签 `nonce‖sid` → AUTH_RESPONSE → 服务端验签、发 ticket 与速率档位 → AUTH_OK。
3. 列目录：LIST → 服务端规范化路径、检查是否在用户根目录内 → LIST_OK 或 ERROR(DENIED)。
4. 上传：OPEN(up, size, root) → OPEN_OK(stream, 0) → 若干 DATA → 每 4 MiB 回一次 ACK → DONE(sha256) → 服务端重算根与摘要 → DONE_OK。
5. 下载：OPEN(down) → OPEN_OK(stream, 0, size) → 服务端推 DATA、客户端回 ACK → DONE → DONE_OK。
6. 断点续传：连接断 → 浏览器收断线、留 stream 与 offset → 重连 → RESUME(ticket) → RESUME_OK(各流 offset) → 双方用块哈希前缀根对账 → 从对上的 offset 继续 DATA。
7. 多文件并发：一次认证下连续 OPEN 多条流 → 各流独立 seq 与 offset → 控制流上流控与限速共用一张令牌桶。
8. 限速：令牌桶按用户档位配速率 → 取不到令牌时暂停发送并在前端显示等待 → 触发阈值回 ERROR(RATE_LIMITED) 或降速。
9. 越权拒绝：LIST 或 OPEN 带 `../`、绝对路径、别人目录 → 服务端 realpath 比对用户根 → ERROR(DENIED)，记审计，连接保留。

## 错误码

| 码 | 含义 |
| --- | --- |
| AUTH_FAILED | 验签失败或公钥未登记 |
| RESUME_REJECTED | 票据无效、过期或被重放 |
| NOT_FOUND | 路径不存在 |
| DENIED | 越权、路径越界、配额不足 |
| BAD_FRAME | magic、ver、length 任一不合法 |
| BAD_STREAM | 流号不存在或已关闭 |
| HASH_MISMATCH | 块或全文摘要不符 |
| RATE_LIMITED | 触发限速 |
| TIMEOUT | 握手、心跳或读帧超时 |
| NOT_IMPLEMENTED | 该版本尚未实现这条消息 |
| INTERNAL | 服务端内部错误 |

## 资源边界

| 项 | 取值 | 作用 |
| --- | --- | --- |
| 帧载荷上限 | 1 MiB | 防长度字段被拿来放大内存 |
| 控制载荷上限 | 64 KiB | 防超长 JSON |
| 握手超时 | 5 秒 | 静默连接活不过握手期 |
| 心跳间隔 | 30 秒 | 及时发现断连 |
| 心跳超时 | 120 秒 | 回收僵死连接 |
| 单连接流上限 | 8 | 防单连接挤占 |
| 单用户连接上限 | 4 | 防单账号耗尽 |
| 单 IP 连接上限 | 16 | 防单点耗尽 |
| 全局连接上限 | 512 | 防总量耗尽 |
| 块大小 | 256 KiB | 续传粒度与校验粒度的折中 |
| 确认间隔 | 4 MiB | 少 ACK 又不至于回退太多 |
| 单文件上限 | 8 GiB | 防配额被打满 |
| 会话保留 | 10 分钟 | 给断线重连留窗口 |

这些是协议层能管的部分。带宽型 DDoS 要上游清洗，报告里写明边界。

## 版本与兼容

`ver` 不匹配时服务端回 HELLO_ACK 带 `ver` 并在错误里说明，随后断开。未知 `type` 记一次计数后丢弃，单连接累计 32 次断开并记审计。
